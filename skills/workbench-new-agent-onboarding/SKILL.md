# 新 Agent 签到工作台（xinwen-workbench）标准流程

给一个新子 Agent 接入 luo 的工作台用。**本版以新人（被接入的子 Agent）视角为主线**：每一步写清你会收到什么、在自己设备上做什么、怎么自验、回什么给主人。盒子侧（主调度 Rumi）的动作只保留你需要知道的部分，标为「盒子侧」。四段提示词全文照抄可用，全部已参数化。不要把真实密钥、口令、指纹写进 skill、工单、记忆或聊天记录以外的任何文件。

适用范围：主调度 Rumi + xinwen-workbench（Docker 版）+ 工单池 agent-bus。只做入职，不做业务派单。

本版的新人侧经验来自 Lei 2026-11-25 的真实入职：凡与模板字面冲突的，以「先核实自己设备的实际状态、再动手」为准，并把冲突报给主人——模板里的常量（钥名、时段、路径）可能是给别人的占位残留。

## 变量（发提示词前先填好）

| 变量 | 说明 | 例子 |
| --- | --- | --- |
| `<AGENT_ID>` | 工单池、聊天、ROSTER、工位目录统一认的名字，不可改 | `muse-5` |
| `<DISPLAY_NAME>` | 工作台显示名，可与 ID 不同 | `muse-5` |
| `<BOX_HOST>` | 盒子地址，主调度 Rumi 所在的服务器 | `1.94.177.113` |
| `<TAILNET_IP>` | 新人 Tailscale IP，`100.x` | `100.x.x.x` |
| `<SSH_FINGERPRINT>` | 新人公钥 SHA256 指纹 | `SHA256:<...>` |
| `<AVATAR>` | 新人默认形象，当前工作台默认是 Jolly | `Jolly` |

约定：时间一律北京时间（Asia/Shanghai）。工作日指周一至周五。

## 占位符确认规则（每填一个停一次）

六个占位符，一个一个确认，不批量、不猜、不跳过：

1. 每填一个占位符就停下来，把拟用的值、来源、会用在哪里报给 luo，等他确认（或改成另一个值）后再填下一个。
2. 表里的例子（`muse-5`、`1.94.177.113`、`Jolly` 等）只是例子，不是默认值，照样要逐个确认，不能直接当真值用。
3. 顺序：先 `<AGENT_ID>`，再 `<DISPLAY_NAME>`，再 `<BOX_HOST>`；`<TAILNET_IP>` 和 `<SSH_FINGERPRINT>` 是新人发回来的，收到后先报给 luo 确认，再写进 ROSTER / `authorized_keys`；`<AVATAR>` 最后确认。
4. luo 改了某个值，全文统一改成新值，不要留旧值。没确认的占位符不发、不写、不建：提示词、ROSTER、工位、容器里都不许出现未确认的 `<...>`。
5. 一次只问一个占位符，不要一次列六个让 luo 一起确认。
6. **新人侧补充**：你收到的提示词里如果还留着别人的占位残留（典型：不属于你的 SSH 钥文件名、不是你的时段），不要照抄执行——用你自己的实际值，并把不一致报给主人。

## 分工

- **luo（主人）**：批 Tailscale 设备、把公钥加进盒子 `authorized_keys`、确认入职完成。只在下面标出的点介入。
- **Rumi（主调度，盒子侧）**：建名册行、建工位、把新人加进工作台三处、发四段提示词、逐项验收。没验过不报完成。
- **新人（它自己的设备）**：装 Tailscale、生成自己的密钥对、搭两个轮询、报额度、上传自己的头像文件。私钥绝不离开它自己的机器。

三条红线，全程不破：一，不发布、不代发消息、不花钱；二，没有工单，不动仓库；三，账号、密钥、口令绝不写进文件。

## 第 0 步：新人先自查（收到提示词 1 之前就做）

先摸清自己设备的硬约束，再动手。查不清就先报主人，不要硬装、硬改：

1. **Tailscale 现状**：本机是否已有客户端、是否已 Connected、平台是否禁止装上游 `tailscale / tailscaled`（托管沙盒常见）。已在网内就不要重装、更不要擅自退网切换——退网会抹掉当前入网身份；主人说的 tailnet 与当前网对不上时，停下来问。
2. **定时任务能力**：你的平台用什么建周期任务（cron / 平台定时任务），时段闸（工作日、午休暂停）能不能写进任务书本身。
3. **额度来源**：你这边的免费额度用什么命令/接口查（百分比 + 重置时间）。先手动跑通一次，再接定时上报。
4. **持久化边界**：哪些目录重启不丢（HOME 类持久区），密钥、脚本、任务书都放持久区。

## 盒子侧准备（Rumi 做，新人只需知道）

发提示词 1 之前，Rumi 会：定 `<AGENT_ID>` / `<DISPLAY_NAME>`（逐个经 luo 确认，查 ROSTER 和 `agents/` 不重名）→ ROSTER 加一行（尾网地址先写 `待补充`、角色 `子 Agent`、状态 `待签到`）→ 建工位 `agent-bus/agents/<AGENT_ID>/` 放三个文件：

- `status.json`：`{"agent": "<AGENT_ID>", "status": "待签到", "role": "子 Agent", "tailnet": null, "last_seen": null}`
- `quota.json`：`{"as_of": null, "note": "待签到后填写", "pct": null, "reset": null}`（签到后按固定格式覆盖写，字段不变）
- `heartbeat.json`：`{"agent": "<AGENT_ID>", "status": "待签到", "last_seen": null}`

并把新人加进工作台三处（聊天列表、指挥中心、原理页，均已动态化：从 `agents/` 工位子文件夹取数，不手改总数；没有工位目录的 Agent 不进聊天列表），重建容器、用 `docker exec` 查容器内文件验收。本地与盒子两边 ROSTER、工位 md5 对上才算完（本地实际落盘 `~/workspace/shared/agent-bus/`，`/opt/shared` 是软链；盒子同一路径 `/opt/shared/agent-bus/`）。

## 提示词 1：加入子 Agent 池（发给新人）

> 请加入主 Muse 的子 Agent 池。先做两件事：
>
> 1. 在你这台设备上装 Tailscale，登录 tailnet，等主人去后台批设备；
> 2. 在你这台设备上生成一对专用的 SSH 密钥（不要复用别人的密钥，私钥不要发出来、不要离开这台机器），把公钥指纹（SHA256）和你的 Tailscale IP（100.x）发给主人。
>
> 做完回一句：Tailscale 已装、指纹和 IP 是什么。

**新人怎么做**

1. 先执行第 0 步的 Tailscale 自查：已 Connected 就直接报 IP，不重装；平台自带客户端且禁止上游版的，用自带那个。
2. 生成**专用**密钥对，文件名带上你自己的标识（如 `~/.ssh/<你的名>-agent-pool_ed25519`），不要用默认钥、更不要用模板里别人的钥名。记下你的实际私钥路径——后面每次 SSH 都要 `-i` 它。
3. 只发三样：公钥指纹（SHA256）、公钥本身、Tailscale IP。私钥永远不发。

**自验**：`tailscale status` 显示 Connected 且 IP 是 100.x；本地 `ssh-keygen -lf <公钥>` 的指纹与你发出去的一致。

**盒子侧**：luo 在 Tailscale 后台批设备、把公钥加进盒子 `/root/.ssh/authorized_keys`；Rumi 核对指纹对得上、钥匙没重复、`authorized_keys` 只多一行。对不上就停。

## 提示词 2：测 SSH、搭工单轮询（发给新人）

> 盒子这边已接好：钥匙已加、名册已入行、工位已建。现在做两件事：
>
> 1. 测 SSH：`ssh root@<BOX_HOST> 'echo HI'`，能回 `HI` 就是通了；
> 2. 搭每 30 分钟轮询工单箱的定时任务（盒子 `/opt/shared/agent-bus/tasks/`），按调度协议领单、干活、回单；搭好后告诉主人你已就绪。
>
> 调度协议：工单一单一目录 `TYYYYMMDD-NNN`，内含 `task.md`（任务、要求、验收标准）+ `result.md`（结果）。领单时在 `task.md` 写认领者 + 时间，状态改 `doing`；做完把结果写回 `result.md`，状态改 `done`。

**新人怎么做**

1. **SSH 测试用你自己的钥**：提示词里的命令可能没带钥、或带着别人的钥名（占位残留）。实测命令形如 `ssh -i ~/.ssh/<你的专用钥> -o IdentitiesOnly=yes -o BatchMode=yes root@<BOX_HOST> 'echo HI'`。默认钥被拒不等于没接好——先换专用钥再下结论。
2. **先读盒子上的调度协议原文再搭轮询**（`dispatch/` 下的 README、task-template、poll-claim.sh 以盒子现行版为准）。工单箱在盒子侧、走 SSH 远程轮询；不要自创一个本机目录版——Lei 第一版就栽在这：盯着一个本机不存在的目录空跑。
3. 领单纪律：先写认领（认领者 + 时间、状态 `doing`）再干活；干完写 `result.md`（做了什么 / 验了什么 / 来源），状态改 `done`。只领指派给你的、`queued` 的单。
4. 碰到钱 / 密码 token 密钥 / 服务器路径这类要主人定的事：停下，写进 `result.md` 并报主人。

**自验**：SSH 回 `HI`（附盒子主机名更稳）；轮询任务已建的证据是任务名 + 周期 + 最近一次运行记录，不是口头「搭好了」。

**盒子侧验收**：新人回的 `HI` 实测结果 + 定时任务证据。SSH 不通先查密钥路径（盒子重建后 `/root/.ssh/` 可能没 key 文件），仍不通就停下来报 luo，不要反复重试同一条路。

## 提示词 3：搭聊天轮询、报额度（发给新人）

> 盒子这边已接好：钥匙已加、名册已入行、工位已建，工作台聊天列表、指挥中心、原理页也都加上你了，头像先用默认的。
>
> 现在搭两样东西：
>
> 1. 轮询网页消息：只在工作日 09:30–23:00，每 1 分钟读一次工作台网页聊天（`/chat`），看到发给 `<AGENT_ID>` 的消息就回，像其他子 Agent 那样；午休 12:00–13:00 暂停，非工作时段的消息等下一时段处理，不要 24 小时轮询。任务名叫 `<AGENT_ID>-chat-poll-1min`；
> 2. 上报免费额度：每 30 分钟把免费额度剩余百分比和重置时间写到盒子 `/opt/shared/agent-bus/agents/<AGENT_ID>/quota.json`，格式固定如下，不要自创别的字段：`{"as_of": "YYYY-MM-DD HH:MM", "note": "免费额度已用 X%，MM-DD HH:MM重置；附加词元剩 Y", "pct": 剩余百分比, "reset": "MM-DD HH:MM"}`。`pct` 是剩余百分比，`note` 里的已用 X% = 100 - `pct`。
>
> 搭好后告诉主人你已就绪。

额度文件格式（固定这一种，不要自创别的字段）：

```json
{"as_of": "2026-11-22 12:00", "note": "免费额度已用 X%，MM-DD HH:MM重置；附加词元剩 Y", "pct": 剩余百分比, "reset": "MM-DD HH:MM"}
```

- `as_of`：这次上报时间，`YYYY-MM-DD HH:MM`，北京时间。
- `pct`：剩余百分比，数字。`note` 里的已用 X% = 100 - `pct`，别写反。
- `reset`：额度重置时间，`MM-DD HH:MM`。
- `note`：照模板填，已用百分比和重置时间与 `pct` / `reset` 对得上；附加词元没有就写 0。
- 每 30 分钟覆盖写一次到盒子 `/opt/shared/agent-bus/agents/<AGENT_ID>/quota.json`，不要追加。

**新人怎么做**

1. **先确认你的聊天内部 id**：盒子侧给你分配的内部 id 可能与 `<AGENT_ID>` 不同（Lei 入职时是 `muse`），走盒子的 chat-helper 读/回/标已读/打心跳，四个动作都认这个 id。搭好后立刻发一条测试消息并读回，证明链路通。
2. **id 会被盒子侧改名**：运行中盒子可能把你的内部 id 改成正式名（Lei 经历过 `muse` → `Lei`，历史文件随之改名）。症状是轮询突然读空——先查是不是改名（看盒子 `chat/` 下的历史文件名），不要当成故障重启了之。改名后把任务书里读、发、标已读、心跳四处 id 一次性全改齐，再排一轮验证。
3. **时段闸写进任务书、连盒子之前就判断**：非工作时段连盒子都不连，消息留到下一时段。时段以主人最新直接指令为准：与模板常量不一致时（实例：模板写 21:00、主人当次定 23:00），按主人的执行，并把不一致报出来。
4. **额度上报**：先手动按格式写一份并读回校验（字段、`pct` 与 `note` 的已用对得上），再接 30 分钟定时。聊天页额度卡有数才算报上去了，文件写了但页面没数等于没报。

**盒子侧验收**：工作日 09:30–23:00 内发一条测试消息给 `<AGENT_ID>`，1 分钟内回上来；午休和非工作时段不轮询、不回（等下一时段）；`quota.json` 30 分钟内有新鲜上报且字段非空、`note` 已用 = 100 - `pct`。

## 提示词 4：头像（发给新人 / Rumi 自己做）

> 工作台中的 `<AGENT_ID>` 用你的默认形象。

**新人怎么做（这一步最容易漏）**：页面上的头像路由和白名单可能早就就绪，**缺的往往只是你自己的头像文件**——「先用默认的」不会把你的形象变出来。把你自己的头像图（PNG）上传到盒子工作台数据目录，文件名固定 `avatar-<AGENT_ID>.png`（盒子 `/opt/xinwen-workbench/data/`，容器内 `/data/`）。

**自验**：用 `docker exec` 在容器内对文件算哈希，与你本地原图一致才算上传到位。**不要用无 cookie 的 curl 验**：工作台未登录请求一律回登录页 HTML，连 `avatar-rumi.png` 都返回 200 的 HTML——200 不是证据，内容类型和哈希才是。页面还显示旧图/默认图，多半是浏览器缓存：头像 URL 带版本号（`?v=N`），升版本号在盒子侧（要改 `app.py` 并重建容器），把这事报给 Rumi / 主人，不要自己重建全舰队共用的工作台。

**盒子侧**：当前工作台默认形象是 Jolly：换成 Jolly，缓存版本号同步升了，页面刷新后头像变了才算完。改完重建容器，用容器内文件验收，不要只看宿主机。

## 入职检查清单（缺一项都不算完）

新人自查与 Rumi 验收共用这一份，每项都要拿得出证据：

- [ ] 每个占位符都已逐个经 luo 确认，无未确认的 `<...>` 残留
- [ ] 新号改名完成，工单池里认这个名（ID、显示名、ROSTER、工位、聊天三处一致）
- [ ] Tailscale 进网，后台已批，尾网地址已分（ROSTER 和 `status.json` 里不再是 `待补充` / `null`）
- [ ] SSH 密钥是专用的，私钥没离开它自己的机器，实际钥路径已记录
- [ ] 指纹对得上，钥匙没重复，`authorized_keys` 行数对
- [ ] 名册 ROSTER 有一行，状态改成 `已签到`
- [ ] 工位目录已建，额度和状态有地方写（`status.json` / `quota.json` / `heartbeat.json` 三个都在）
- [ ] 工作台三处都加上了：聊天列表、指挥中心、原理页（动态取数，不手改总数）
- [ ] 头像文件已上传（`avatar-<AGENT_ID>.png` 在盒子数据目录、容器内哈希与原图一致），缓存版本号已同步升
- [ ] 聊天轮询只在工作日 09:30–23:00 跑，午休 12:00–13:00 暂停；内部 id 与盒子现行名一致
- [ ] 额度每 30 分钟上报，格式是 `{"as_of", "note", "pct", "reset"}`，聊天页额度卡有数

全部打勾后，Rumi 把 ROSTER 状态改成 `已签到`，`status.json` / `heartbeat.json` 的 `last_seen` 写上首次心跳时间，再向 luo 汇报：谁入职了、每项怎么验的、证据是什么。

## 常见失败

| 现象 | 先查什么 |
| --- | --- |
| SSH 被拒，密钥没变 | 盒子 `authorized_keys` 是否还有这把 key；本机 ssh 默认密钥路径（重建后 `/root/.ssh/` 可能为空），改带 `-i ~/.ssh/id_ed25519` |
| 提示词里的钥名 / 路径对不上 | 模板占位残留（别人的钥名），换成你自己的实际专用钥路径再测 |
| Tailscale 装不上 | 平台可能禁止上游版且自带客户端——先查自带客户端是否已 Connected，已在网就不要重装、不要擅自退网 |
| 工单轮询空跑、没单 | 是不是在盯一个本机目录？工单箱在盒子侧，走 SSH 远程轮询；先读盒子 `dispatch/` 协议原文再搭 |
| 聊天轮询突然读空 | 盒子侧可能改了你的内部 id（历史文件随之改名）；查 `chat/` 下文件名，四处 id（读/发/标已读/心跳）一起改 |
| 改名 / 加人后页面还是旧的 | 只改了宿主机源文件、容器没重建；用 `docker exec` 查容器内文件 |
| 总数还是 5 个 / 名单缺人 | 某处还是硬编码数字，改成从 `agents/` 子文件夹动态取 |
| 额度卡没数 | `quota.json` 字段名 / 路径是否照已有那份；上报时间是否在 30 分钟内 |
| 聊天半夜还在回 | 轮询没加工作日 09:30–23:00 + 午休暂停的时间判断 |
| 头像还是默认图 / 不显示 | 先查盒子数据目录里有没有 `avatar-<AGENT_ID>.png`（多半是文件根本没上传）；有文件还不对，看浏览器缓存与 URL 版本号，报盒子侧升版本，不要拿无 cookie 的 curl 200 当证据 |

## 相关位置

- 工单池：`/opt/shared/agent-bus/`（本地 `~/workspace/shared/agent-bus/`），规则 `DISPATCH.md`，名册 `ROSTER.md`
- 工作台：盒子 `/opt/xinwen-workbench`，Docker 容器，端口只发布到宿主机 `127.0.0.1:18080`；头像等静态文件在 `data/`（容器内 `/data/`）
- 主调度规则：Rumi 唯一主调度，luo 只跟 Rumi 对话；先拆工单再派活，验收通过再汇报。
